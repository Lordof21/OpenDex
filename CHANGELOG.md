## [0.9.3] - 2026-11-15

### Added

- **No adb on the computer? The start-up screen now says so and installs it with one click.** OpenDeX does not bundle adb, and without it the start-up screen used to end on "no phone connected" and the pairing dialog — which needs adb too — so a first-time user could not tell what was missing. The backend now looks for a working adb at every start (`OPENDEX_ADB_PATH`, the file picked on this screen, `PATH`, its own copy, the Android SDK — the first that runs `adb version` wins) and tells the screen; when there is none the step list gives way to a short flow in the same card: **Otomatik kur** (the obvious one), **Kurulu olanı seç…** (a native file picker for an adb the user already has) and **Resmi sayfayı aç**. The install reads Google's own SDK manifest, takes the newest *stable* platform-tools for this OS (the same file also lists dev builds), downloads the zip over HTTPS from dl.google.com, checks its size and SHA-1 against the manifest, unpacks it beside the final folder (refusing a corrupt zip, entries that would land outside it, a zip bomb), starts the new `adb` once and only then swaps it into `~/.opendex/platform-tools` — nothing else on the system changes (no `PATH`, no registry, no administrator rights), and a failure at any step leaves what was there as it was. One bar follows it honestly (download most of the way, then verify and install, with real megabytes), "Vazgeç" stops it and removes what it started, a failure says what went wrong and what to do (no internet, a download that did not verify, no write access, an antivirus that blocked the new `adb.exe`), and an adb the user installs or picks by hand is noticed without a click (the screen looks again every few seconds and the moment the window is focused again). When adb is found the card shows "adb hazır · sürüm …" for a moment and the boot goes on where it was; the desktop never opens underneath the flow, the 25 s start-up limit waits for the user, and `GET /api/devices` and the bootstrap no longer poll a missing executable. New routes `GET /api/adb`, `POST /api/adb/recheck`, `/install`, `/install/cancel`, `/locate`; `GET /api/startup` gained `adb` (`checking | ok | missing`) and `adb_version`; settings `OPENDEX_ADB_CHOICE_FILE`, `OPENDEX_ADB_MANAGED_DIR` and `OPENDEX_ADB_MANAGED_ONLY` (only OpenDeX's own adb and the picked file count: shows the "no adb" screen on a computer that has adb, or pins one adb no other tool can swap).
- **"Refresh" on the desktop** (right-click menu, and Ctrl+R). It reads the app list and the saved layout again and makes every icon ask again (an icon that had failed showed its letter until now), for the times a load came up incomplete. It never touches the layout. Ctrl+R belongs to the phone app while a phone window has focus, and is ignored in a text field; the browser's own page reload is blocked on the desktop.

### Changed

- **The window Hub is about a third shorter, and every setting shows its choices.** It ran to ~750 px in a browser window and scrolled even in a default-size window. Settings with several values (scale, dynamic DP, header mode, pre-landing) used to step through them one click at a time behind a "Rotate" label; they are now rows with all their values visible (one click picks one), and under "Follow general" the row says what applies right now. "Key layout" appeared twice (a tile and a row); it is now one row that opens the editor, with a switch beside it that turns the layout off and on. The window tiles (full screen, separate PiP, keep on top, display lock) sit in one row of small tiles, and so do "Send to Workspace", "Reload page" and "Restart app" at the bottom; their longer descriptions moved into tooltips. The top band shows the app's icon and name and the stream's size and density instead of a fixed title and a "LIVE" badge. The smallest text went from 9 to 10 px. The Hub opens right below a PiP's slimmer header (it left a 16 px gap), and the window Hub and the Workspace task Hub are now the same width; the task Hub's window tiles also sit in one row.
- **A narrow DeX window header drops buttons instead of overflowing them.** Below about 400 px the header leaves out "Reload page" (it is in the Hub); below about 330 px it also leaves out audio and "Send to phone" (a right-click on the header still offers it). A PiP header keeps "Send to phone".
- **The Workspace PiP wears the same frame as a stream PiP.** The OS title bar and the black strip are gone: the same slim header (also floating over the picture in hover mode, coming down when the cursor hits the top edge fast), the same edge-resize handles, the Workspace's own Hub (a Workspace task is a crop window: no stream/screen actions) and — on hovering "maximize" — a layout menu like Windows 11's that puts the window on a zone of the screen: six layouts (halves, 3/5 + stack, a third + two thirds, two thirds + a third, half + stack, quarters) and a full-screen bar. Back, audio and "send to phone" act on the source task.
- **One layout menu everywhere.** Hovering "maximize" opens the same six-layout menu (halves, 3/5 + stack, a third + two thirds, two thirds + a third, half + stack, quarters, and a full-screen bar) in DeX windows (in-app snapping), in the stream PiP and in the Workspace PiP (the OS window is placed on that zone of the screen). DeX windows had four layouts.
- **A window shown in a PiP gets a taskbar preview, like a DeX window.** The card used to find no picture for it (the canvas lives in the PiP's webview): while the card is open the PiP is asked for a small picture of its canvas a few times a second and it goes to the same cache a minimized window uses.
- The new start-up "adb gerekli" flow, the Hub's scale / header rows and the pairing-code digit labels are translated into all 18 other languages (AI translation, not reviewed by native speakers).

### Fixed

- **A restart of the adb server no longer closes the windows.** The adb server (the PC's side of every adb forward, `adb shell` and scrcpy session) can vanish — nothing in the adb log (no USB trouble, no clean exit) and no crash record in Windows; a new one starts at the next adb call. Every scrcpy server dies with it, and each virtual display with its server, which takes the app's task along. The connection supervisor is meant to rebuild such windows in place (`heal_links`), but it recognised a dropped link only by a changed adb transport id, and a NEW adb server numbers its transports from 1 again: the phone was transport 1 before and after, nothing looked changed, no rebuild was armed — and the presence monitor then saw an empty display and closed the window as "closed on the phone" (field log 2026-11-15 12:58: Instagram's window closed 5 s after the adb server vanished, its display destroyed and the app killed). Now the device tracker counts every time its stream to the adb server ends (it was up, then it closed — not when we stop it ourselves), the supervisor treats a changed count as a dropped link and arms the in-place rebuild (also asked by a window whose server died, through `link_dropped`), and the presence monitor does not judge a window whose scrcpy server is dead while the link is down (a Workspace member follows the shared Workspace server) — a live server with an empty display still means the app was really closed. The rebuild starts the app again on a fresh display (an app's state does not survive its display). The loss of the server is logged as `[DeviceTracker] adb sunucusuyla bağlantı koptu`, and the rebuild as `[SUPERVISOR] adb sunucusu yeniden başladı`.
- **"İkisi" microphone calibration: the phone's and the computer's chirps stay together.** The computer released its audio output after 4 s without audible sound, which is most of a calibration run when the music is paused: the output went to sleep in the middle of the run (both runs in the field log), the page's remaining chirps froze on its timeline and played whenever the output woke up again — often during the NEXT run, on top of the phone's first chirps ("the PC is on its third chirp, the phone on its first") — and the recording lost the rest. A run now keeps the output up from start to end, cancels its chirps that are still to come when it ends or is cancelled (and a previous run's, when it starts), and refuses to write a result when the audio clock fell behind the page clock during the run ("recording interrupted") instead of measuring a timeline that moved. Every run writes one `[FE:audio] sync_calibration` line to the backend log (pairs heard per side, spread, the clock's error, how much lead the first chirp had).
- **The "Çok kanallı mikser" panel no longer scrolls sideways.** Every tooltip is drawn all the time, only transparent, and an absolutely placed box counts towards its scroll container: the one-line tooltip of "İkisi" in the output selector at the panel's right edge stuck out past it and gave the panel a horizontal scrollbar. A hidden tooltip is now shrunk to nothing (after its fade-out), so no panel scrolls for an invisible tooltip; the outer segments of a segmented control open their tooltips inward, and the mixer's list never scrolls sideways.
- **"İkisi" in Auto lines the phone and the computer up more closely.** The page learned the phone's clock through one probe that went page → backend → phone and back, so its error was half the round trip of both hops together. The backend now keeps its own fix on the phone's clock (quick adb pings timed with the high-resolution counter, refreshed in the background, the quickest and freshest one used) and answers the page at once from it with how far off it can be (`POST /audio/clock` gained `err_ms`); the page keeps the probe with the least total error (half its localhost round trip + `err_ms`, plus the drift since it was taken) and refreshes every 5 s instead of 15 s, with samples aging out after 30 s instead of 90 s.
- **A header opened by hover no longer stays open when the window moves under the cursor.** Picking a layout from the maximize menu, handing a window back from the phone or resizing it moves the window under a still cursor, so no `mouseleave` came and the slid-down header stayed for good. A DeX window now checks where the cursor really is (`:hover`, which counts the layout menu hanging below the header) and closes it after about half a second once it is not on the header — never cutting short the one second a header stays down after a fast edge hit. In a PiP the header goes back to its normal closing rule as soon as the layout menu or the Hub closes (nothing scheduled the close when they went away under a cursor that did not move).
- **The keymap "Transparency" setting is visible in the editor.** The editor drew every node fully opaque, so moving the slider (say to 95 %) changed nothing the user could see; the setting only applied in play. The editor now previews it on every node but the selected one (never lower than 35 %, so a node stays easy to grab).
- **The PiP's layout menu looks like the DeX one and stays open.** The PiP header forced every button inside it to 24 px, which also squashed the layout menu's zones; it now leaves menu items alone. A header that floats over the picture closed when the cursor went down into the menu (the menu hangs below the strip): the header is kept down while the menu is open.
- **A PiP resizes like a DeX window: ghost box, then a smooth settle on the first frame.** Dragging an edge used to resize the OS window live, which stretched the picture, or — with the picture held — showed a black area when growing and cut the picture off when shrinking. Now the PiP keeps its box and its picture for the whole drag, and the dashed ghost (with the size in physical pixels) is a transparent, click-through window of its own drawn over the desktop at the box being made. On release the window still keeps its box, the ghost stays at the target with a pulsing dot, and the stream is asked for the new size through the same pending transition a DeX window uses; when the first frame of the new size arrives the ghost goes and the window eases into the target box while the picture stretches from the old fit to the new one (VideoCanvas's resize morph). If nothing is asked (fixed display, resizing off) the window settles at once; if no frame comes it settles after the 5 s DeX limit, so the ghost can never stay on screen. The ghost window is made when the cursor first reaches an edge and lives as long as the PiP. The Workspace PiP resizes the same way (it settles at once and the task is then resized to the new box). A resize Windows makes itself (keyboard, edge snap) still asks for the new size after the mouse button is up; the shell answers "is the button still down?" off its main thread.
- **Switching a header from hover to pinned (and back) no longer squeezes or stretches the picture** — in every window, the global setting and the per-window mode alike. The header is added ABOVE the picture: a 500 px picture stays 500 px and the window becomes 500 + header tall, growing upward; against the top edge the window is pushed down smoothly instead (and gives that back when the header goes). It used to take the header's height out of the picture, which was then scaled and asked of the phone again. The same holds for PiP windows (the OS window grows upward / is pushed down, animated).
- **A Workspace task shown in a DeX window or a PiP is now 1:1 with the screen, and nothing is resized when it opens.** The cropped window used to be sized by fitting the whole Workspace display into the DeX area (or the PiP's screen), so on a Windows scale of 125 % the frame was smaller than the task's pixels and the picture was resampled on every frame (soft text). The scale is now one stream pixel = one physical pixel (1 / devicePixelRatio) whatever the window size, the frame includes the header as it is at that moment (also when it opens with the header hidden), and when the crop is within a few pixels of the viewing area the canvas takes the crop's own size on whole physical pixels. A task that fits opens exactly as it is: no `resize-task`, no density change. The PiP window has no header strip of its own any more (the OS frame moves and closes it) — the black bar and its "Bring to front" button are gone; the picture is the whole window. "Bring to front" stays inside a DeX window.
- **Refreshing the app list no longer wipes OpenDeX's own desktop icons and your folders from the saved layout.** The refresh treated everything that is not in the phone's launcher list as an uninstalled app, and OpenDeX Settings, OpenDeX Files and the folders never are: they vanished from the desktop (and from the database) at every refresh, from the taskbar's app drawer as much as from the new desktop "Refresh". Only real phone packages are pruned now. The same refresh also saved twice from one stale list when an app had been removed and another added, which brought the removed ones back. Icons that an old refresh already wiped come back at their default cell the next time the desktop loads (an icon you hid yourself stays hidden).
- **Keys pressed while an IME is composing belong to the IME** (Japanese, Chinese, Korean). Enter and Esc no longer commit or cancel half-typed text in the rename fields, path bar, file search, app launcher, language and settings search, folder and template names (a half-typed name could be saved to disk, an app launched, the language switched and the page reloaded). A source-scanning test fails when a new Enter handler on a text field lacks the guard.
- **Pasting into the app's own text fields no longer reaches the phone**, and Ctrl+V reaches only the focused phone window (every open window used to take it).
- **The saved theme applies before the first paint** (no light-to-dark fade at startup); native controls follow the theme (`color-scheme`).
- **Dialogs move focus in, keep Tab inside and give focus back** when they close; menus and sheet tabs answer the arrow keys; unlabeled inputs got names (pairing code digits each have their own).
- **Closing a PiP window ended the backend** in the installed / portable app: the shell shut the backend down when *any* window was destroyed, not only the main one, so "Send to phone", "Back to desktop", "Send to Workspace", the close button and Alt+F4 in a PiP all killed the session (the reclaim panel never appeared). Only the main window ends the app now. It never showed in `tauri dev`, where the backend is not the shell's own child.
- **"Send to phone" from a PiP no longer closes the PiP.** The window stays where it is and shows the "on the phone — take it back" veil (the same one a desktop window gets); "Take back" in it returns the picture to the PiP. The command used to go to the main window and the PiP closed at once, so the veil was never seen (and a failure toast went to a window nobody looked at: a failed send now shows in the PiP and lifts the veil). The send runs in the PiP's own store; the backend's `app_handoff_to_phone` event reaches that webview too. Coming back from the phone, the window is no longer re-fitted for the desktop window's box (or, inside the PiP's store, for the whole desktop): the PiP takes one look at its own canvas and asks the phone only if the stream does not fit.
- **Keyboard shortcuts in the PiP window**: the window-manager layer lives in the main window only, and the video canvas does not forward the keys it recognises to the phone, so Ctrl+G, Ctrl+W, Ctrl+M, Ctrl+Shift+F… did nothing at all in a PiP. The PiP now reads the same shortcut table and applies what makes sense for one OS window: Ctrl+G switches the key layout on / off (the way out of game mode; the layout store is shared, so the main window follows), Ctrl+W closes (like the ✕), Ctrl+M minimizes, Ctrl+Shift+F toggles full screen, Ctrl+Alt+Down sends the window to the Workspace, and Esc leaves full screen *without* being sent to the phone. Ctrl+W / Ctrl+M still go to the game in game mode. Alt+Tab, Win+arrows and the like are swallowed (meaningless for one window).
- **Ctrl + wheel zoom follows the mouse tip, and only outside game mode.** The pinch the wheel sends to the phone now has the mouse tip as its focal point exactly, tick by tick (it was smoothed toward the pointer, so the point under the mouse lagged and the picture slid), and next to a screen edge the two fingers are shifted inward as a pair instead of being clamped one by one (a clamped finger changes the distance between them, which the phone reads as zoom: zooming near an edge wobbled in and out). In game mode Ctrl frees the mouse, so Ctrl + wheel there is a plain scroll, never a zoom (desktop windows and the Workspace).
- The PiP window shows its own notifications (key layout on / off, page reloaded, connection lost…): it is a separate webview and had no toast host, so they were never seen. The title bar's "Reload page" button is no longer hidden in a PiP (the Hub row already worked there).
- A window that moves to a PiP and back is no longer reconfigured: the PiP opens at exactly the size of the picture the desktop window shows (its canvas + the PiP's own border and header), so the stream already fits and nothing is asked of the phone (no size / density change, no re-fit of the app). The first size request used to be made before the canvas was measured, from the desktop window's 44 px title bar, and was never corrected — the picture was 56 px short and soft until the first manual resize. Back on the desktop the window's own header mode decides its size, and nothing is asked when the stream is still the one it had.
- "Stretch" (Uzat) did nothing when the picture was a few pixels short of its box: the pixel-grid snap that keeps "Fit" crisp pinned the canvas to the stream's own size in every fit mode, so the thin black rim stayed. Only "Fit" snaps now; "Stretch" and "Crop" fill the box.
- The desktop came back clean after a restart: a saved layout with more than twenty icons was taken for a legacy dump and reset to the defaults (and saved over), a layout that could not be read yet (phone not bound) looked like "nothing saved", and a desktop emptied on purpose was refilled. A saved layout is now the user's, whatever its size; only a layout that was never saved starts from the defaults. Folders are saved with the layout (they were kept only in the browser storage, which is separate for `tauri dev` and the installed app); `GET /api/layout` answers `409` without a bound phone instead of `[]`, and `AppLayoutEntry` gained an optional `custom` item.
- App icons: an icon already on this PC's disk is served without a phone (they turned into letters while the phone was binding or away) and is kept in memory; the response carries an `ETag` and `Cache-Control: private, max-age=86400` instead of `no-cache`, so a window no longer asks again for every icon it draws. Refreshing an icon still bypasses all of it.

## [0.9.2] - 2026-11-11

### Added
- **Pre-landing is now a choice: Automatic / On / Off**, for every window and for the whole system. Before a window goes to the phone, OpenDeX can bring its virtual display to the phone's own size and density, so the app is rebuilt behind the PC veil instead of on the phone. *Automatic* (the default, what the old switch did when it was on) skips it for an app that would be rebuilt both at the pre-landing and at the move, so its page is not reloaded twice; *On* does it on every eligible send; *Off* never does it (size and DPI change on the phone in one step, with the move). Where to set it: the window's Hub (a new "Pre-landing" row under the window tiles, cycling *Follow general → Automatic → On → Off*), DeX Settings › Window (this window only) and › System (general), and Settings › Windows. A window's own choice wins over the general one and travels with the hand-off request (`POST /api/windows/handoff` takes `prelanding`); the `handoff_prelanding` setting is now `"auto" | "on" | "off"` (an old `true` / `false` is read as `auto` / `off`). Why it exists: X keeps a separate feed position for the wide and the compact layout, so a hand-off that switches between them loses the place wherever the switch happens.

### Changed
- A browser window that only changes size keeps its process: after a resize at another density the settle no longer restarts Chrome (every page used to reload from its top); the tab watcher already gives every tab the window's scale.
- Resizing a browser window keeps the place of the page in front: the place is read before the display changes and put back afterwards (measured: 1440 → 448 → 1440 px kept page 30 of a chapter at 50 / 50.2 / 50.5 %).
- The desktop UI shows the app's real version (v0.9.2) on the start screen; the installer and the portable package carry it in their file names (`OpenDeX_0.9.2_…`), so a new installer upgrades an installed one.

### Fixed
- A reader's place on pages that scroll an inner box (a site's mobile layout scrolled a full-height box while the window had 56 px, so the page came back at its top) is found and restored by whatever scrolls the page.
- A manga reader that keeps the tallest height a page ever had left 78–103 px of nothing under every page after a narrower width: the tab watcher now notices pages left at the old width's heights and reloads them to the place of before.
- A watcher that cannot reach the browser no longer holds a hand-off for its whole timeout; its socket closes in 0.3 s instead of waiting 10 s for a close frame Chrome never sends.

### Performance
- Handing a browser to the phone no longer shows the desktop page for 2–5 s first. The site is decided before the move: when the pre-landing put the window's display at the phone's own size and density, the phone's tab watcher starts there and the move waits (at most 3.5 s) until the tab in front is the right site. Whether a site serves another page to the other identity is remembered per site and direction (24 h), re-checked behind the decision so a stale answer is corrected in the same hand-off; a page the watcher reloads is restored at DOMContentLoaded with the browser's own scroll restoration held off.

### Translations
- The new strings are translated into 18 languages.

## [0.9.1] and earlier

### Added
- Multi-app sound (the phone's "several apps play at once" flag): Settings › Sound card with the live state, the time of the last reading and a **Check again** button; one-click, read-back-verified **Turn on** (policy *Ask* by default, *Always*, *Never*); restored when the last window closes; a once-per-run offer when one app pauses another; a mixer pill and a DeX panel shortcut. New daemon command `audio_multi_focus` (rebuild the helper jar), `GET/POST/PUT /api/audio/multi-focus`, event `multi_audio_focus_update`, setting `multi_audio_focus_policy` ([design/MULTI_APP_SOUND.md](docs/design/MULTI_APP_SOUND.md)).
- First public documentation set: README (EN/TR), install, architecture, API (with a generated OpenAPI 3.1 document and reference), configuration reference, phone-helper protocol, audio, security model, testing, troubleshooting, FAQ, roadmap.
- `tools/screenshots`: documentation images generated from the real UI against sample data.
- `OPENDEX_NO_OBFUSCATE=1` / `build_release.py --no-obfuscate` for plain, debuggable builds.
- Drift tests that fail when generated documentation, the OpenAPI document, the sample-data fixtures or the daemon-protocol tables fall out of step with the code.

### Fixed
- The OpenDeX Settings window now shows in the taskbar like any other task (icon, open / active / minimized state; click minimizes or restores it) — the entry was missing, so it never appeared.
- "Maximize" on the Settings window no longer slides under the taskbar: its stage ends above the taskbar strip (and follows a screen resize).
- `Ctrl` + mouse wheel (and `Ctrl` `+` / `-` / `0`, touchpad pinch) zooms the desktop UI in the native window like in Chrome (`zoomHotkeysEnabled`; WebView2's zoom control was off). Over a phone window `Ctrl` + wheel is still the pinch gesture sent to the phone.

### Changed
- Device manager (docs/design/DEVICE_MANAGER.md): a phone's USB and Wi-Fi links are one device (the backend reads each link's ANDROID_ID once: `DeviceInfo.android_id`), saved devices are matched to it by identity instead of a guessed `ip:port`, and adb's own state (unauthorized, offline) reaches the UI with what to do about it. The Device Center has a USB | Wi-Fi link switcher with an in-progress state, inline confirmations (closing windows, forgetting), a right-click / ⋯ / Shift+F10 menu (connect, switch link, disconnect, rename, copy serial or IP, forget) and in-place renaming (`PATCH /api/devices/known/{android_id}`, `KnownDevice.alias`). One "Cihaz bağla" dialog replaces the QR panel: my devices (plugged in, on the network, saved, USB instructions) next to the pairing methods.
- Quitting the desktop app ends the backend gracefully: the shell asks first (`POST /api/system/shutdown`, so windows close and the phone's scrcpy servers and virtual displays stop) and kills the sidecar only if it has not ended within 8 s — a kill skips that cleanup. If the shell dies without asking (crash, Task Manager), the backend notices its `OPENDEX_PARENT_PID` is gone and ends itself the same way instead of staying orphaned on port 8710.
- Tapping a notification sends its own PendingIntent onto the window's display (daemon `notif_invoke launch`, sender mode `ALLOW_ALWAYS` — the plain mode is blocked for a shell sender on Android 16) instead of rebuilding an `am start` from the intent's text, which dropped the extras and fell back to the app's home feed; focusing a window no longer starts the app's launcher page on top of it (`hold_launch`). It is the only path: the per-app routes and the Tier 1/2/3 ladder (`deep_navigator`: 632 → 213 lines) are gone, so a failure is logged with its reason and `POST /api/notifications/open` answers `ok: false` instead of hiding it.
- Quick settings: the master volume slider is gone (it moved the DeX output and the phone's media volume at once); per-app audio and the phone's own Android streams remain. The six toggles keep a fixed size at the top of a panel whose height no longer depends on the page.
- The OpenDeX apps (Files, Settings, Phone mirror, Workspace) have their own icon artwork (`frontend/src/assets/icons`).
- `scripts/build_release.py --pyinstaller` builds the backend sidecar with PyInstaller (about a minute, ~31 MB) instead of Nuitka; the spec excludes the unrelated packages of a crowded dev environment.
- The security headers (`nosniff`, `no-store`, …) are now also sent on the `401`/`403`/`411`/`413` answers of the middleware.
- `docker-compose` publishes the UI on loopback only.
- Release builds keep the WebView inspector (right-click → Inspect, F12) available; the obfuscator options that fight an inspector are off.
- The installer is built in Turkish (`OpenDeX_0.1.0_x64_tr-TR.msi`), the only language the interface has.
- The backend log file gets INFO and above by default; log and telemetry files older than 7 days are deleted at start and the folder is kept under 150 MB.
- The stream HUD (F8) is hidden by default.
- "İkisi" audio: the DeX copy starts with a 60 ms jitter margin (was 30), raises it faster after late chunks and gives it back after three calm minutes (was 48 s), so a resize burst on Wi-Fi is less likely to cut the sound.

### Fixed
- "Bağlantıyı kes" did not keep the phone disconnected: the bootstrap (and every API call through `ensure_device`) bound the still-plugged cable or the open Wi-Fi link again within seconds. A user disconnect now pauses automatic connecting until the user picks a device (`auto_connect_paused` in the device state), and the connect dialog opens with their devices. On USB it also ran a bare `adb disconnect`, which dropped every other wireless link adb held; only the session's own Wi-Fi link is released now.
- "Back to USB" could pick another phone's USB link; it now only offers the same phone's. Picking another phone no longer tries to migrate this phone's windows onto it: the session changes cleanly (`device_lost` reason `device_switch`) after the UI asked whether the open windows may close. `POST /api/device/bind` answers `502` with the reason instead of a `500`.
- Battery page: a placeholder design capacity (Xiaomi's power profile says 1000 mAh) no longer hides the real capacity; when the battery takes more than the port's reported limit (a vendor fast charger on a stale 500 mA / SDP default) the measured value wins and the "slow port" verdict is not drawn; long values wrap instead of being cut with "…". The "reaches N °C in 10 min" extrapolation is gone, only the measured trend is shown.
- Saved Wi-Fi networks listed once per security type (WPA2 + WPA3 under one id) produced duplicate React keys; they are folded into one row.
- File manager, phone layout: "Up" and previewing with ←/→ no longer leave a file selected (which switched the toolbar into selection mode).
- The taskbar panels are `forwardRef` components, so `AnimatePresence` can measure them (React "ref is not a prop" / "Function components cannot be given refs" warnings).
- "İkisi" audio was silent on the phone on Android 12+: the phone-side track waited for its whole (large) buffer to fill before starting, so the aligned writer dropped every chunk. The track now starts after 10 ms of data.
- The backend terminal no longer prints every flow when `OPENDEX_LOG_LEVEL=DEBUG` is set (media covers, notifications, temperatures and every RPC flooded it). That level now only adds DEBUG lines to the log file; the terminal shows the flows named in `OPENDEX_TRACE`.
- Audio on a weak or unstable link: the Android ≤ 12 session stream reopens itself when its adb socket ends (it stayed silent until a window opened); the phone → PC channel never loses a stream's end, sends a keepalive when idle and is reconnected when it goes silent; the browser's playback cushion adapts to the link instead of a fixed 50 ms. The phone-side part needs a rebuilt `opendex-tools.jar`.
- File manager: grid thumbnails were requested for the folder instead of the file, so they never showed.
- Notification cards forward their ref (React warning inside `AnimatePresence`).
- A phone that adb lists but cannot talk to ("device offline") no longer causes an endless bind/reload loop: failed binds now back off (2 s … 30 s) for API callers too, and the QR pairing panel is not torn down by the momentary "connected" state of a failing attempt.
- A phone that adb reports as offline / unauthorized is no longer asked again by every background loop at once (eleven `adb.exe` processes in two seconds for one app-list request): after adb's verdict the same phone is not asked for 2 s, until the device list changes. Uncaught adb errors answer `503` with a readable sentence instead of a `500` and a page-long traceback.
- Opening or resizing an app no longer costs a dozen `pidof` round trips to the phone: the density reconciler now waits for "the process died / was reborn" on the phone in one shell call instead of asking every 0.15–0.25 s (it falls back to asking when the phone cannot run the loop).
- The phone helper (`opendex-tools.jar`) compiles again against the public SDK (compile-only `IContentProvider` stub), and the release exe no longer embeds the builder's home directory.

### Removed
- Obsolete planning and analysis reports from the repository root; the compiled backend sidecar and developer-specific files from version control.
